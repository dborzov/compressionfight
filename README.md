# Choose Your Codec

An interactive course in data compression codec design, with a game and a set of introduction articles.
Live at https://www.borzov.ca/compressionfight/ (the Map: https://www.borzov.ca/compressionfight/map/).

**The game.** Pick a compression task (a general-purpose file archive, photographs for the web, real-time
speech, LLM weights on a laptop, a KV cache resident in HBM…), read its requirements, and assemble a codec
pipeline stage by stage from a catalogue of 47 algorithms. A live pipeline runs real toy math on sample data
and shows honest bit counts (raw → entropy bound → final), the side information the decoder must hold, and
the distortion. Running the pipeline grades each stage against the task's requirements and names the real
codec. Five levels (lossless basics, lossy coding, shared priors, ML-era formats, KV cache), a tutor, lessons,
checkpoint quizzes, twelve hands-on exercises, and an Explore mode (real codecs as pipelines, an algorithm
catalogue with an interactive lab for every entry, a requirements matrix, head-to-head comparisons, trade-off maps).

**The Map.** Twenty introduction articles, one per algorithm family, written to `docs/map/style.md`: a
question first, a toy example with real numbers, the proper definitions, the interactive lab from the game,
figures generated by the included Python scripts, and connections to the rest of the field. `docs/map/map.md`
is the taxonomy that organises them.

Open `index.html` in a browser for the game (no build step). The Map is built with Hugo from `docs/map/` into
`map/` by `./build.sh`.

## The model behind it

Every practical codec is a pipeline of the same stages:

| Stage | Question it answers |
|---|---|
| Transform | Which directions carry the energy? |
| Prediction | What can be guessed from what is already decoded? |
| Quantization | How many bits per value, and where may error go? (the only lossy stage) |
| Entropy coding | How are skewed symbols turned into bits? |
| Perceptual model | What will the consumer not notice? |
| Shared prior | What does the decoder already hold before the stream arrives? |

A task's requirements (lossless or not, latency tolerance, encoder and decoder compute, random access,
bandwidth pressure, decoder memory, whether side information may be shipped) meet an algorithm's properties
(delay, cost on each side, random-access friendliness, compression, memory). The scoring rules in
`js/rules.js` name the requirement and the property that collide; that collision is the lesson.

## Layout

- `js/data.js` the catalogue: stages, families, algorithms, tasks, real codecs, synergies and conflicts, comparisons, links into the Map
- `js/curriculum.js` tutor lines, lessons per level, checkpoint quizzes, trade-off presets
- `js/quests_data.js`, `js/quests.js` the twelve exercises
- `js/engine.js` the toy pipeline (LZ77, Huffman, arithmetic/ANS estimates, Golomb-Rice, DCT, k-means, block int4, RoPE, SVD…)
- `js/rules.js` scoring
- `js/demos.js` an interactive lab per algorithm
- `js/viz.js`, `js/ui.js`, `css/style.css`, `index.html` the front end
- `img/` portraits and posters, generated locally (FLUX.2 Klein) in an Art Nouveau style
- `docs/map/` the Map sources (`map.md`, `primer.md`, `zoo/<slug>.md`, figure scripts, images); `site/` the Hugo project; `map/` the built output
- `docs/` contracts the modules were built against (`ARCHITECTURE.md`, `DEMOS.md`, `SIDEQUESTS.md`), the content policy, the design system, and the KV-cache research notes
- `test/` node tests: `node test/engine_test.js`, `node test/demos_test.js`, `node test/quests_test.js`
